# Vault Bootstrap — 知识库框架搭建

完全自包含的知识库脚手架工具。不依赖任何外部文件，可在任意设备上从零搭建一个符合框架规范的空知识库。

---

## 执行流程

### 第一步：确认目标路径

向用户确认新知识库的目标绝对路径。若用户未指定则主动询问。

如果目标目录已存在且非空，警告用户并询问合并还是取消；不存在则直接创建。

### 第二步：创建目录结构

在目标路径下创建完整目录树。每个叶子目录放置 `.gitkeep` 空文件（空目录可被 git 追踪）。

```
{VAULT_ROOT}/
├── 0.raw/
│   ├── assets/
│   ├── articles/
│   ├── papers/
│   ├── books/
│   └── data/
├── 1.entities/
├── 2.concepts/
├── 3.summaries/
├── 4.comparisons/
├── 5.synthesis/
├── 6.queries/
├── _templates/
└── _scripts/
```

（共 13 个目录，含 8 个叶子目录放 `.gitkeep`）

### 第三步：写入模板文件（4 个）

以下 4 个模板文件均内嵌于本 skill，**严禁试图从母库读取**。将文件内容逐字写入对应路径，模板中的 `_system` 标签保留不变。

### 第四步：生成核心骨架文件（4 个）

#### 文件 4.1：`CLAUDE.md`

````markdown
# CLAUDE.md — Wiki 操作规范

本文件是 LLM Agent 维护此知识库的核心配置。所有操作必须遵循此规范。

---

## 目录结构

```
{VAULT_NAME}/                       (Vault 根 = Wiki 本体)
├── CLAUDE.md                      # 本文件：LLM 操作规范
├── index.md                       # 内容索引（按类别组织，每次 ingest 后更新）
├── log.md                         # 操作日志（按时间追加，每次操作后更新）
├── overview.md                    # Wiki 总览 / 知识路线图
│
├── 0.raw/                         # 原始资料（不可变，LLM 只读不写）
│   ├── assets/                    # 图片/附件
│   ├── articles/                  # 网页剪藏
│   ├── papers/                    # 学术论文
│   ├── books/                     # 书籍章节
│   └── data/                      # 数据文件
│
├── 1.entities/                    # 实体页：人物、组织、地点、角色、产品等
├── 2.concepts/                    # 概念页：理论、思想、方法论、术语等
├── 3.summaries/                   # 来源摘要：每个原始资料对应一页
├── 4.comparisons/                 # 对比分析：多来源横向比较
├── 5.synthesis/                   # 综合洞察：跨来源提炼的结论/论文
├── 6.queries/                     # 查询存档：有价值的问答固化为永久页面
│
├── _templates/                    # Obsidian 模板
└── _scripts/                      # 辅助脚本
```

## 核心操作

### 1. Ingest（摄入来源）

用户将新资料放入 `0.raw/` 后触发。流程：

1. **读取**原始资料，调用'literature-organizer'提取关键信息
2. **讨论**：向用户汇报关键发现，确认要强调的重点
3. **写入 Wiki**：
   - 在 `3.summaries/` 创建来源摘要页（格式见 [[_templates/来源摘要页]]）
   - 更新 `1.entities/` 中相关实体页（只创建公司企业和科研机构，无需创建人物和期刊）
   - 更新 `2.concepts/` 中相关概念页（新建或追加）
   - 若与已有内容矛盾，在页面中标注 `> [!conflict]`
   - 若有跨来源关联，更新 `5.synthesis/` 相关页面
   - 更新`overview.md`
4. **更新索引**：在 `index.md` 中注册新页面
5. **追加日志**：在 `log.md` 中记录本次操作

### 2. Query（查询）

用户提问时：

1. **先查 index.md** 定位相关页面，查询时不要阅读其中的实体（1.entities/）
2. **读取相关页面**，必要时追溯到 `0.raw/` 原始资料
3. **合成回答**，附带引用链接 `[[page]]`
4. **判断是否存档**：如果回答有长期价值，主动建议写入 `6.queries/`

### 3. Lint（健康检查）

定期执行，检查项：

- [ ] 矛盾：搜索 `> [!conflict]` 标注，评估是否需要解决
- [ ] 孤页：找到没有任何 `[[backlink]]` 指向的页面
- [ ] 缺页：是否有重要概念被提及但缺少独立页面
- [ ] 过时：是否有被新资料推翻的旧论断
- [ ] 断链：Wiki-link 指向不存在的页面
- [ ] 可搜索：是否有可通过网络搜索填补的知识空白
- [ ] 图片缺失：是否有抽象概念或架构技术的解释未从原文获取图片

各类型页面的模板文件存放在 `_templates/` 目录中，创建新页面时读取对应模板：

| 模板文件 | 适用目录 | 说明 |
|---------|---------|------|
| [[_templates/来源摘要页]] | `3.summaries/` | 原始资料摘要 |
| [[_templates/实体页]] | `1.entities/` | 人物、组织、地点、产品等 |
| [[_templates/概念页]] | `2.concepts/` | 理论、思想、方法论、术语等 |
| [[_templates/存档查询页]] | `6.queries/` | 有价值问答的永久存档 |

## 命名规范

| 类型   | 命名格式                         | 示例                               |
| ---- | ---------------------------- | -------------------------------- |
| 来源摘要 | `YYYY-MM-DD 标题.md`           | `2026-05-27 Karpathy Wiki方法论.md` |
| 实体   | 实体全名                         | `Andrej Karpathy.md`             |
| 概念   | 概念名                          | `检索增强生成.md`                      |
| 对比   | `A vs B.md` 或 `A 与 B 的对比.md` | `RAG vs Wiki方法.md`               |
| 综合   | 描述性标题                        | `LLM知识管理最佳实践.md`                 |
| 存档查询 | 问题摘要                         | `如何高效管理个人知识库.md`                 |

---

## 注意事项

1. **所有 Wiki 内链接使用 `[[wikilink]]` 格式**
2. **原始资料 `0.raw/` 中的文件绝不修改**
3. **每次操作后必须更新 `log.md`**（追加一行）
4. **每次 ingest 后必须更新 `index.md`**
5. **矛盾处使用 Obsidian callout**: `> [!conflict] 新旧论断矛盾说明`
6. **置信度低时使用**: `> [!todo] 待验证/待补充`
7. **index.md 超过 ~200 条时考虑分类拆分或引入搜索工具**
8. **图片调用'figure-extractor'从原文截取，绝对不要自己生成**
9. **严格按照模板内容撰写**
10. **清理 `0.raw/assets` 中每次截取获得的无用图片**
````

## 关键约束

6. **`{VAULT_NAME}` 从目标路径提取最后一级目录名**。
